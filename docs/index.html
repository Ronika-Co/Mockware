mockware

Generate mock SDK layers for embedded unit testing — parse real SDK headers, generate stub implementations, and override any function at test time.

Get started → GitHub
bash 
# Phase 1: Parse SDK headers into a knowledge base
$ mockware parse $IDF_PATH -o known_apis.yml

# Phase 2: Generate mock SDK for your project
$ mockware generate \
    --project . \
    --input known_apis.yml \
    --output mock-sdk

# Phase 3: Build and run tests
$ cmake -B build && cmake --build build
$ ./build/test_runner
All tests passed!

Features

Designed for real-world embedded projects, not just demos.

🎯

Function-pointer overrides

Every stub exports a _fp pointer. Per-component *_fakes.h headers declare them as extern—just include and assign in tests.

📂

Mirrored include paths

Generated headers preserve the SDK directory structure. #include "driver/gpio.h" just works.

🔁

Reusable YAML base

Parse once, generate many times. Share known_apis.yml across projects and CI runners.

🧩

Framework-agnostic

Works with ESP-IDF today. Designed to support Zephyr, STM32 HAL, and any C/C++ embedded SDK.

⚡

Minimal runtime

Function pointers add zero overhead in release builds. Swap them out freely in test builds.

📝

Auto-generated defaults

Functions return sensible defaults (ESP_OK, NULL, 0) based on return type. Override only what you need.

Quick start

Three commands to go from SDK headers to passing tests.

1

Parse SDK headers

Point mockware parse at your SDK installation. It scans every component and builds a complete YAML knowledge base of macros, types, enums, structs, and function declarations.

# Build the knowledge base
mockware parse $IDF_PATH -o known_apis.yml

# Or target specific components
mockware parse $IDF_PATH \
    --components esp_wifi,nvs_flash,driver \
    --output known_apis.yml
2

Generate mock SDK

The generator scans your project for SDK #include directives, then produces stub headers + implementations — only for what you actually use.

mockware generate \
    --project . \
    --input known_apis.yml \
    --output mock-sdk
3

Link and test

Add the generated CMake target to your test build and link against it.

# In your test CMakeLists.txt
add_subdirectory(mock-sdk)
target_link_libraries(my_test PRIVATE mock_sdk)

Installation

Python 3.10+ required. gcc needed for header parsing.

uv tool install mockware
pip install mockware
# From the repo root
uv run mockware --help
