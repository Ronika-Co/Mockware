mockware

Generate mock SDK layers for embedded unit testing — auto-detect missing external SDK dependencies, generate stub implementations, and override any function at test time.

Get started → GitHub
bash 
# Phase 1: Auto-detect missing external dependencies
$ mockware scan . -o missing_apis.yml

# Phase 2: Generate mock SDK for your project
$ mockware generate \
    --project . \
    --input missing_apis.yml \
    --output mock-sdk

# Phase 3: Build and run tests
$ cmake -B build && cmake --build build
$ ./build/test_runner
All tests passed!

Features

Designed for real-world embedded projects, not just demos.

🎯

Function-pointer overrides

Every stub exports a _mock pointer. The generated mockware/fakes.h declares them all as extern—just include and assign in tests.

🔍

Auto-detect missing deps

Scans your source files for #include directives, finds which referenced headers don't exist in your project, and creates YAML entries automatically.

🧠

Inference from usage

Function signatures, types, macros, enums, and structs are inferred from your code. All definitions are global — no attribution noise across headers.

🔁

Non-destructive merging

Use --mode partial to merge newly discovered deps into your existing YAML. Manual edits are never overwritten.

🧩

Function-like macros

YAML values starting with ( generate #define NAME(value) (no space). Supports FreeRTOS-style macros like pdMS_TO_TICKS: (x) ((uint64_t)x).

📦

Auto standard includes

The generator scans for uint64_t, size_t, bool, FILE etc. and automatically adds #include <stdint.h>, <stddef.h>, etc. to types.h.

Quick start

Three commands to go from project source to passing tests.

1

Auto-detect missing dependencies

Point mockware scan at your project. It scans source files for #include directives and finds headers that aren't in your project tree or include paths. The tool infers function signatures, types, macros, enums, and structs from usage context.

# Auto-detect missing external deps
mockware scan /path/to/project -o missing_apis.yml

# Re-scan: merge new detections, preserve edits
mockware scan /path/to/project \
    --existing missing_apis.yml \
    --mode partial \
    --exclude "mock-sdk/**"
2

Generate mock SDK

The generator scans your project for SDK #include directives, then produces stub headers + shared definition headers (in mockware/) + implementations.

mockware generate \
    --project . \
    --input missing_apis.yml \
    --output mock-sdk
3

Link and test

Add the generated CMake target to your test build and link against it.

# In your test CMakeLists.txt
add_subdirectory(mock-sdk)
target_link_libraries(my_test PRIVATE mock_sdk)

YAML format reference

The 6-section format used by the scan output and generator input.

headers:
  esp_wifi.h:
    includes: [esp_err.h]
  freertos/Freertos.h:
    includes: []

types:
  esp_err_t: int

macros:
  ESP_OK: "0"
  pdMS_TO_TICKS: (x) ((uint64_t)x)  # function-like → no space

enums:
  wifi_mode_t:
    values:
      WIFI_MODE_NULL: 0
      WIFI_MODE_STA: 1

structs:
  wifi_init_config_t:
    definition: |
      typedef struct { int member; } wifi_init_config_t;

functions:
  esp_wifi_init:
    return: int
    params: ["wifi_init_config_t* config"]
    header: esp_wifi.h
    body: "return 0;"
  vTaskDelay:
    return: int
    params: ["uint64_t arg"]
    header: freertos/Freertos.h

Function fields

FieldRequiredDescription
returnYesReturn type string (defaults to "void")
paramsYesList of typed params, e.g. ["int x", "void* buf"]
headerNoHeader path for attribution → source/<path>.c. Missing → source/general.c
bodyNoCustom stub body. Default: return 0; (or NULL for pointers)
kindNo"inline" for static inline functions (body is full declaration)

Testing with custom fakes

Every generated stub exposes a function pointer you can reassign.
